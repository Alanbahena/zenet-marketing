## 3. Three-session demo structure · FLEXIBLE (no rígido)

### 3.1 Reframe canonical · structure flexible NO mandato rígido

> **Three-session demo es la estructura canonical de referencia · NO mandato de 3 reuniones rígidas. El insight load-bearing es multi-stakeholder engagement pre-cierre. Se comprime o expande según lane + warmth + org size.**

### 3.2 Insight load-bearing vs estructura

| Layer | Qué es | Load-bearing? |
|---|---|---|
| **Insight real** | Multi-stakeholder engagement pre-cierre (Owner + Manager + Chef + Contable) · multi-threading 68% = 3x conversion | ✅ SÍ · estructural |
| **Estructura propuesta** | 3 sesiones formales separadas (Manager → Chef → Owner) | ⚠️ Es UNA forma de lograr el insight · NO el único camino |

**El error a evitar:** tratar "3 sesiones" como mandato rígido cuando el insight real es "engage los stakeholders correctos antes del cierre".

### 3.3 Mapping a 3-lane timing

| Lane | Sessions realistic | Cuándo |
|---|---|---|
| **Fast (4-8 sem)** | 1-2 sesiones comprimidas (multiple stakeholders juntos) | Warm network · founder-led · small org · **Phase 0 design partners** |
| **Standard (8-16 sem)** | 2-3 sesiones (algunas separadas) | Moderate warmth · Phase 1 commercial |
| **Slow (16-30+ sem)** | 3+ sesiones formales separadas | Cold · larger org · Multi-Sitio complex · skeptical buying committee |

### 3.4 Phase 0 reality

**Phase 0 cohort 5 design partners (warm network · founder-led · selective) = likely Fast lane comprimido 1-2 sesiones.** NO over-engineer con 3 rigid sessions × 5 partners (founder bandwidth waste).

### 3.5 Per-session playbooks como referencia

Las secciones §4-6 detallan cada stakeholder playbook · útiles como referencia. En Fast lane se combinan (Manager + Owner misma sesión típico). En Standard/Slow se separan. **Los playbooks son contenido de referencia · NO secuencia obligatoria rígida.**

### 3.6 Qué NO cambia (insight preserved)

| Preserved canonical | Detalle |
|---|---|
| Multi-stakeholder engagement pre-cierre | Owner + Manager + Chef + Contable engaged (en 1 sesión o 3 · pero engaged) |
| Multi-threading 68% | Single-thread sigue 3x lower conversion |
| Contable parallel track | Silent veto mitigation load-bearing |
| Per-stakeholder messaging | Owner ROI · Manager operational · Chef workflow · Contable compliance |
| His-numbers-displayed | Pre-prep ask canonical |

## 4. Sesión 1 · Manager playbook

### 4.1 Objetivo

Workflow assessment · operational champion development · 60-90 min (cf. `02-customer-research/04-customer-journey.md` v0.7 §3).

### 4.2 Pre-session prep · his-numbers ask

Canonical (cf. `04-customer-journey.md` v0.7 §3.6.7 · heredado doc 03 §5.6):

> "Antes de vernos · mándame foto de 5 facturas recientes + lista de tus 10 recetas más vendidas. Así te muestro algo con TUS números · no genérico."

**Razón:** converts generic show-and-tell a his-numbers-displayed · dramatically higher engagement.

### 4.3 Session structure

| Block | Duración | Contenido |
|---|---|---|
| Rapport + context | 10 min | Operación actual · pain mapping inicial |
| Discovery deep (SPIN) | 25 min | Situation · Problem · Implication · Need-payoff |
| Workflow demo (his-numbers) | 30 min | Agency working con SUS datos · NOT generic |
| Q&A + next steps | 15 min | Manager questions · Sesión 2 Chef setup |

### 4.4 SPIN questioning canonical

Dentro three-session Sesión 1 (technique within framework · cf. doc 00 §3.5):

| SPIN | Pregunta ejemplo |
|---|---|
| Situation | "¿Cómo manejas hoy el inventario entre sucursales?" |
| Problem | "¿Qué pasa cuando no estás en la sucursal?" |
| Implication | "¿Cuánto te cuesta cuando se rompe la operación sin ti?" |
| Need-payoff | "¿Qué cambiaría si tuvieras claridad de ambas sucursales sin estar ahí?" |

### 4.5 Manager messaging angle

Operational value · workflow simplification · tiempo recuperado (daily-use lens · cf. doc 03 §5.4).

### 4.6 Manager as champion

Manager usa diariamente → Manager se vuelve internal advocate · si Manager NO adopta → silent churn risk Mes 6. Cultivate Manager como champion para Sesión 3 Owner cierre support.

### 4.7 Exit criteria

Manager engaged + operational champion + Sesión 2 Chef agendada (o combinada Fast lane).

## 5. Sesión 2 · Chef playbook

### 5.1 Objetivo

Recetario + augmentar criterio · adoption stickiness · 30-45 min.

### 5.2 Session structure

| Block | Duración | Contenido |
|---|---|---|
| Rapport (chef-specific) | 5 min | Respeto al criterio chef |
| Recetario demo (his recipes) | 25 min | Standardization + augmentar NO reemplazar |
| Adoption framing | 10 min | "Aumenta tu criterio" NO "te reemplaza" |
| Q&A | 5 min | Chef concerns |

### 5.3 Chef messaging angle

Augmentar criterio · NO reemplazar (valor canónico #1 "Aumentar, no reemplazar" · cf. `Branding/mision-vision-valores.md`).

### 5.4 Chef adoption critical

Chef adopta = stickiness · Chef resiste = churn risk. Chef es adoption gatekeeper · su buy-in load-bearing para retención.

### 5.5 "Aumentar no reemplazar" framing

Valor canónico aplicado · anti-replacement anxiety:

| Anti-frame (NO) | Frame correcto (SÍ) |
|---|---|
| "Zenet hace tu trabajo" | "Zenet aumenta tu criterio · tú decides" |
| "Automatiza tus recetas" | "Estandariza para que tu equipo replique tu criterio" |
| "Te reemplaza el sistema" | "Extiende tu conocimiento a donde no estás" |

### 5.6 Exit criteria

Chef engaged · adoption signal positive · NO replacement anxiety.

## 6. Sesión 3 · Owner playbook + cierre

### 6.1 Objetivo

ROI synthesis + pricing deep-dive + cierre · 20-30 min.

### 6.2 Session structure

| Block | Duración | Contenido |
|---|---|---|
| ROI synthesis | 10 min | Value summary · his-numbers ROI |
| Pricing deep-dive + justificación | 10 min | Arbitraje 70-100x + competitive anchoring DUAL |
| Cierre conversation | 10 min | Decision + next steps |

### 6.3 Pricing en sales motion · CORRECCIÓN (NO reveal secreto)

> **Sesión 3 NO es "primera vez que ve precio"** (landing ya muestra pricing público cf. doc 03 §4.6). Es **pricing deep-dive + justificación con his-numbers + cierre** cuando value-established AND Owner-present.

| Stage | Pricing interaction |
|---|---|
| Landing (pre-sales) | Cliente VE pricing público con value framing (transparency) |
| Demo 1-2 | Pricing NO foco · value building · his-numbers |
| Sesión 3 Owner | Deep-dive · justificación arbitraje · cierre conversation |

**El Owner probablemente YA vio el precio en la landing.** En Sesión 3 NO revelamos secreto · **contextualizamos + justificamos + cerramos**.

### 6.4 Pricing justificación canonical

Justificación uses arbitraje 70-100x + competitive anchoring DUAL (cf. doc 03 §5):

| Layer | Talking point |
|---|---|
| Arbitraje 70-100x | "$1,799/sucursal vs equipo humano $105K-185K/mes que haría este trabajo" |
| Wallet calibration | "Está en la banda de software que ya conoces (Bistrosoft $1,599 · PoloTab $1,490)" |
| Category claim | "Pero ellos te dan POS+inventario · Zenet te da agencia de 8 especialistas · same wallet, different category" |
| His-numbers ROI | "Con TUS números · esto te recupera X horas/mes + previene Y pérdida" |

### 6.5 Excepción pregunta directa

Si Owner pregunta precio Demo 1 (común MX SMB directo):

| Approach | Status |
|---|---|
| ❌ Evasión total ("no te puedo decir hasta verte el value") | NO · destruye trust MX SMB |
| ✅ Honest rango + value framing inmediato | SÍ · transparency + contextualiza |

**Ejemplo:**
> "Claro · te soy directo · el rango es $1,500-1,799 por sucursal al mes según el plan. Pero déjame mostrarte rápido POR QUÉ vale eso · comparado con contratar el equipo que haría este trabajo, estás hablando de una fracción. ¿Te muestro con tus números?"

### 6.6 Owner messaging angle

ROI · tranquilidad operativa · escalamiento ordenado (financial decision lens · cf. doc 03 §5.4).

### 6.7 Cierre mechanics

Intent confirmation → handoff 10-step lifecycle (doc 02 SF §8):
- Phase 0 SF: intent confirmation email/WhatsApp → Tier 2.0 lawyer → DocuSign signing
- Phase 1 commercial: intent → click-wrap MSA onboarding flow

### 6.8 Exit criteria

Owner intent confirmed → cierre stage (Negociación + agreement → Cierre).

## 7. Contable parallel track + silent veto mitigation

### 7.1 Frame · Contable silent veto risk

Heredado `02-customer-research/05-buying-process.md` v0.7 §10.8:

> Contable externo puede ejercer **silent veto** · NO objeta abiertamente pero retrasa/bloquea authorization (CFDI concerns · LFPDPPP · "no entiendo el sistema"). Silent veto NO se detecta sin engagement proactivo.

### 7.2 Contable parallel track from Stage C

Contable engaged en parallel track desde Stage C (NO espera hasta cierre). Early engagement = silent veto mitigation.

### 7.3 Contable concerns canonical

7 contable-specific objections (cf. `06-objeciones.md` v0.5 §3.7.5):

| Concern | Disarming |
|---|---|
| ¿XMLs? | CFDI 4.0 compliance · auto-generation |
| ¿CONTPAQi? | Integration/coexistence · NO reemplaza tu sistema contable |
| ¿catálogos SAT? | Compliance handling correcto |
| cliente no entiende | Education framing · simplicidad |
| ¿PAC? | PAC integration · timbrado automático |
| suscripción no incluye contador | Clarify scope · Zenet NO es despacho · es facilitador |
| LFPDPPP | Data protection compliance · encargado del tratamiento |

### 7.4 Silent veto diagnostic

| Signal | Implication |
|---|---|
| Contable no responde a engagement | Possible silent veto brewing |
| Owner dice "déjame consultar con mi contador" repetidamente | Contable concern unaddressed |
| Authorization delays sin razón clara | Silent veto active |
| Contable absent de conversations | Engagement gap · risk |

### 7.5 Contable messaging angle

CFDI compliance · data limpia defensa SAT · LFPDPPP comfort (compliance lens · cf. doc 03 §5.4).

### 7.6 Anti-silent-veto framework

| Mitigation | Action |
|---|---|
| Early engagement | Contable parallel from Stage C · NO espera cierre |
| Address concerns proactive | 7 concerns disarmed before objection |
| Education framing | Contable entiende value · NO se siente bypassed |
| Compliance reassurance | CFDI + LFPDPPP + PAC handled correctly |
| Respect contable authority | Contable autoriza · NO bypass · include in decision |

## 8. LAER MX-adapted objection handling

### 8.1 LAER framework

Heredado `02-customer-research/06-objeciones.md` v0.5 §5 · MX-adapted (high-power-distance + non-confrontational + collectivist context):

| Step | Acción |
|---|---|
| **L · Listen** | Escucha completa · NO interrumpir · entender objeción real |
| **A · Acknowledge** | Validar concern · "entiendo por qué lo dices" · NO defensive |
| **E · Explore** | Preguntas para entender root · "¿qué te preocupa específicamente?" |
| **R · Respond** | Address root concern · NO argument-winning · relationship-preserving |

### 8.2 9 disarming techniques (MX-adapted)

| # | Technique |
|---|---|
| 1 | Validate before respond (acknowledge concern legitimacy) |
| 2 | Question to understand root (NO assume objeción superficial) |
| 3 | Peer reference (operador conocido lo resolvió así) |
| 4 | Honest acknowledgment of limitation (NO oversell) |
| 5 | Reframe to value (redirect a beneficio · NO feature) |
| 6 | Time/cost of inaction (pain cost framing · NO pressure) |
| 7 | Social proof MX-specific (peer evidence) |
| 8 | Founder transparency (honest founder POV) |
| 9 | Defer to discovery (si objeción premature · "veámoslo con tus números") |

### 8.3 7 anti-patterns (NO hacer)

| # | Anti-pattern | Razón |
|---|---|---|
| 1 | Pressure tactics | MX cultural violation · relationship damage |
| 2 | Argument-winning | Win argument lose sale · MX non-confrontational |
| 3 | Premature ROI math | Trust building first · NO calculator pre-relationship |
| 4 | Vendor self-defense | MarketMan G2 case · defensive = lose trust |
| 5 | Interrupting | Disrespect · LAER Listen violation |
| 6 | Dismissing concern | Invalidates operator · trust loss |
| 7 | Over-promising | Honesty violation · churn setup |

### 8.4 Objection catalog por categoría

8 categorías (cf. `06-objeciones.md` v0.5 §3):

| Categoría | Ejemplo objection | LAER response |
|---|---|---|
| **Price** | "está caro" | Arbitraje 70-100x + value framing (cf. §6.4) |
| **Trust** | "no te conozco" | Peer reference + founder visibility |
| **Timing** | "ahorita no" | Pain cost framing (NO pressure) |
| **Identity** | "yo SOY el sistema" | "extiende tu sistema" (cf. §8.5) |
| **Complexity** | "es complicado" | Zero-training UX |
| **Contable** | (7 specific cf. §7.3) | Compliance framing |
| **Competition** | "ya uso X" | Coexistence 95% framing (NO replacement) |
| **Adoption** | "mi equipo no va a usar" | Multi-stakeholder + WhatsApp accessibility |

### 8.5 Identity objection canonical · "yo SOY el sistema"

Load-bearing insight (cf. `02-customer-research/07-voice-of-customer.md` v0.1.1 V-010):

| Anti-frame (perceived attack) | Frame correcto |
|---|---|
| ❌ "Tu negocio no tiene sistema" | ✅ "Zenet extiende tu sistema a donde tú no estás" |

**Razón:** operador NO percibe ausencia de sistema · percibe que él ES el sistema. Cualquier mensaje que implique "no tienes sistema" es perceived attack on identity. Mensaje correcto: extensión NO reemplazo.

### 8.6 Price objection deep

Post pricing deep-dive (Sesión 3) · LAER + arbitraje + NO heavy discount:

| Owner dice | LAER response |
|---|---|
| "está caro" | L: escucha · A: "entiendo, es una inversión" · E: "¿comparado con qué lo ves caro?" · R: arbitraje 70-100x + his-numbers ROI |
| "déjame pensarlo" | L/A: validar · E: "¿qué te haría falta para decidir?" · R: address specific |
| Negotiation request | Honest: descuento Socio Fundador estructurado (Phase 0) · NO ad-hoc heavy discount (anchor erosion) |

### 8.7 Mexican cultural dynamics

| Dynamic | Application |
|---|---|
| Non-confrontational | NO argument-winning · relationship-preserving |
| High-power-distance | Respeto · NO presión agresiva |
| Collectivist | Peer reference > individual logic · social proof |
| Relationship-first | Trust building precede selling |
| Confianza | Honest + transparent · long-term relationship |
