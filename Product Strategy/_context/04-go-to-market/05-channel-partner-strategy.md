## 2. Frame · channel philosophy

Tres principios canónicos que gobiernan toda decisión channel/partner.

### 2.1 Principio #1 · Value exchange + aligned incentives

> **Priorizar partners por value exchange claro + incentivos alineados · NO por "acceso a customer base" solo.** Un partner sin value exchange claro es asimétrico · NO sustainable.

La pregunta correcta para priorizar NO es "¿quién tiene acceso a restaurantes?" · es **"¿con quién el value exchange es claro Y los incentivos están alineados?"**

### 2.2 Principio #2 · Demand-side first · supply-side con leverage ⭐

> **Two-sided marketplace bootstrapping:** Zenet adquiere restaurantes (demanda) PRIMERO vía consultor + contador + direct (Phase 1-2). Distribuidores/suppliers (oferta) se unen Phase 2+ CUANDO Zenet tiene base = leverage para value exchange invertido. NUNCA intentar supply-side antes de demand-side.

**Regla canonical marketplace:** nunca intentes el lado de oferta antes de tener el lado de demanda.

| Lado | Orden | Razón |
|---|---|---|
| Demanda (restaurantes) | PRIMERO (Phase 0-2) | Zenet adquiere vía consultor + contador + direct |
| Oferta (distribuidores/suppliers) | DESPUÉS (Phase 2+) | Se unen PORQUE hay demanda agregada · leverage Zenet |

### 2.3 Principio #3 · Channel disciplina phase timing

> NO channel activation Phase 0-1 · founder-led direct first · channel ramp Phase 1.5+. Channel partnership requiere reputation + validation (case studies) · premature = daño reputational.

### 2.4 Anti-philosophy

| NO hacemos | Razón |
|---|---|
| Supply-side partners early (asimétrico) | No leverage · demand-side first violation |
| Channel partnership pre-validation | Reputation risk · case studies required |
| Partners sin value exchange claro | Asimétrico · unsustainable |
| "Acceso a customer base" como único criterio | Ignora aligned incentives |

## 4. Consultor partner program (#1) · modelo extensión Zenet

### 4.1 Frame · #1 priority demand-side

Consultor partners son #1 channel priority porque value exchange es el más fuerte + incentivos perfectamente alineados: el consultor monetiza su servicio sobre Zenet + da mejor servicio a SUS clientes (restaurantes con quienes ya tiene trust).

### 4.2 Modelo extensión Zenet (SoftRestaurant+SYCA replica al revés)

Heredado `01-industry-and-market/06-estructura-y-ecosistema.md` v1.0.1 §14:

| Modelo SoftRestaurant+SYCA TJ | Modelo Zenet+consultor |
|---|---|
| SYCA implementa + entrena + maneja relación cliente SoftRestaurant | Consultor introduce + co-markets · **Zenet CS maneja implementation** |
| SYCA monetiza service + implementation fees | Consultor gana revenue share + better service to clients |

**Diferencia clave:** Zenet hipótesis consultor es **intro/referral/relationship** · NO full implementation (Zenet CS handles implementation directly). Modelo más light que SYCA · más scalable.

### 4.3 Pre-validated consultor partners

Validación cualitativa ya hecha (cf. `06-estructura-y-ecosistema.md` §14 + `07-geografia-y-expansion.md` §16.3):

Estos consultores ya validaron cualitativamente el modelo "consultor partner como extensión Zenet".

| Herramienta para monetizar (revenue share + service fees) | Clientes (restaurantes con trust pre-establecido) |

| Brand association (early Zenet partner) | Peer reference + authority (consultor recomienda = trust) |

## 5. Contadores/despachos channel (#2) · silent veto → ally

### 5.1 Frame · el doble rol estratégico del contador

El contador tiene rol doble que lo hace estratégicamente único:

| Dimensión | Detalle |
|---|---|
| **Buying committee** | Contable autoriza · silent veto risk (cf. doc 04 §7) |
| **Channel potential** | Many restaurant clients (20-50+ per despacho) · authority + peer reference |

### 5.2 El move estratégico · convertir silent veto en channel ally

> **Mismo stakeholder · opuesto impacto.** Contador objeta = pierdes deal. Contador recomienda = te trae 20-50 restaurantes.

Convertir el silent veto risk en channel ally es estratégicamente poderoso · transforma un riesgo en un asset.

### 5.3 Value exchange · data limpia + referral

| Zenet aporta a contador | Contador aporta a Zenet |
|---|---|
| Data limpia/reconciliada (facilita CFDI · DIOT · conciliación) | Referrals · authority endorsement |
| CFDI defense vs SAT (data limpia = defensa auditoría) | Trust signal (contador recomienda = strong peer reference) |
| Posible referral fee | Many restaurant clients (20-50+ per despacho) |
| Menos trabajo manual reconciliación | Client base access |

### 5.4 Tension a manejar · Zenet NO es despacho

Frame canonical "facilitador NO certificador" (cf. `01-industry-and-market/08-entorno-regulatorio.md` §8.4):

| NO hacer | SÍ hacer |
|---|---|
| ❌ Posicionar Zenet as accounting replacement | ✅ Zenet hace el trabajo del contador más fácil (data limpia) |
| ❌ Competir con contador | ✅ Contador recomienda Zenet · gana referral + better data |
| ❌ Bypass contador | ✅ Include contador as ally · respeta su authority |

**Razón:** Zenet NO es despacho contable · es facilitador. El partnership con contadores debe ser: Zenet hace su trabajo más fácil → ellos recomiendan/refieren. NO competir.

### 5.5 Individual contador vs despacho

| Tipo | Characteristic | Channel value |
|---|---|---|
| Contador individual | Relationship · few clients | Phase 1 (design partners' contadores) |
| Despacho contable | Scale · 20-50+ restaurant clients | Phase 1.5+ (channel scale) |

### 5.6 Phase timing

| Phase | Status |
|---|---|
| Phase 1 | Exploration · design partners' contadores (convert silent veto → ally) |
| Phase 1.5 | Despacho channel exploration · scale potential |
| Phase 2 | Despacho channel ramp |

### 5.7 Anti-patterns contador channel

| NO hacemos | Razón |
|---|---|
| Bypass contador (compete) | Silent veto activation · ally NOT enemy |
| Position Zenet as accounting replacement | "Facilitador NO certificador" frame |
| Ignore contador concerns | Silent veto risk · relationship damage |

## 7. Distribuidores/La Canasta · Phase 2+ supply-side platform con leverage

### 7.1 Reframe · de "channel #1 asimétrico" a "supply-side platform Phase 2+" ⭐

> **La Canasta NOT channel para adquirir restaurantes early** (asimétrico · no leverage). **ES supply-side platform partner Phase 2+** CUANDO Zenet tiene base de clientes = leverage para value exchange invertido.

### 7.2 Leverage inversion

| Momento | Value exchange con distribuidor |
|---|---|
| **Early (sin base de clientes)** | ❌ Asimétrico · "promueve Zenet a tus clientes" · ¿por qué lo haría? No hay demanda |
| **Phase 2+ (con base sólida)** | ✅ **Invertido** · "tengo X restaurantes que necesitan insumos · únete y recibe demanda agregada" · AHORA Zenet tiene leverage |

### 7.3 Two-sided marketplace bootstrapping

| Lado | Orden | Cómo |
|---|---|---|
| Demanda (restaurantes) | PRIMERO (Phase 0-2) | Zenet adquiere vía consultor + contador + direct |
| Oferta (distribuidores) | DESPUÉS (Phase 2+) | Se unen PORQUE hay demanda agregada · leverage Zenet |

**Regla canonical:** nunca intentar supply-side antes de demand-side. La Canasta como #1 early violaba esto.

### 7.4 Value exchange Phase 2+ concreto

| Zenet aporta a distribuidor | Distribuidor aporta a Zenet |
|---|---|
| Demanda agregada (X restaurantes pedidos recurrentes) | Supply + fulfillment |
| Pedidos automatizados (Zenet cognitive nucleus orquesta) | Transaction/platform fee |
| Nuevos clientes (restaurantes que NO eran suyos) | Logistics + delivery |
| Data/insights demanda (qué · cuándo · cuánto) | Pricing competitivo |
| Predictibilidad (forecasting demand) | Early-mover platform position |

### 7.5 Platform vision connection

Esto es literalmente el **"Uber Eats B2B procurement"** model · Zenet como **cognitive nucleus** orquestando pedidos restaurante → supplier:

```
Restaurant cliente Zenet:
  ↓ ordena via Zenet agency interface
Zenet AI agents:
  ├─ Recomiendan qué ordenar (inventory + ventas + recetario)
  ├─ Optimize procurement (precio · timing · supplier)
  └─ Send orders to suppliers via Zenet platform
       ↓
Suppliers (multi-supplier marketplace):
  ├─ La Canasta (BC + BCS + Sonora)
  ├─ Otros distribuidores regionales
  └─ Direct supplier brands
       ↓
Zenet captura value (transaction fees · cognitive insights · marketplace economics)
```

Cross-ref: `Market Research/05-market-insights/01-vision-plataforma-zenet.md` v0.1 + `06-experience-y-roadmap/00-cs-as-agents-vision-nota.md` (platform vision) + `02-features-y-scope/01-roadmap-hipotesis-fase-1.5-y-2.md` v0.1 F8 partner channel.
